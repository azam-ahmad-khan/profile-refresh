# Gap → proof of work

A profile *says* what someone can do. Proof of work *shows* it in public. The gap is the distance between what the
target roles ask for and what a stranger can verify today.

## 1. Find the gap

1. From 2–3 real job postings for the target roles, list the 5–8 skills or experiences that keep recurring.
2. For each one, mark the owner's **public** evidence: Strong (a public artifact or a named role), Weak (only a claim on
   the profile), or None.
3. Pick the **one** gap that matters most for the target roles and that a side project can realistically close.
   Experience that needs a job title or a licence can't be closed this way. Say so plainly.

## 2. Propose one project

Give a short pitch: the problem, what the finished thing is, where it will live publicly, the skills it shows, a
realistic size (aim for 1–3 weekends), and a first step to take today. Rules:

- Built **from scratch** on personal time and accounts. No employer data, documents, code, templates or client
  material, even reworked. Show something generic that has the same shape as the work.
- Small and finished beats big and half-done. A clear README or summary page matters as much as the work.
- It must be public and linkable (repo, portfolio page, article, video, certificate page).

Before pitching, sanity-check the idea on six questions (adapted from career-ops' `project` mode). Drop or reshape
any idea that fails question 1 or 5:

1. Would a hiring manager for the *target* role care? (most important)
2. Is it different from the thousand tutorials on the same topic?
3. Can someone see it working in two minutes (a link, demo, video or page)?
4. Will it produce an honest, checkable outcome to quote?
5. Can a first version ship in a weekend or two?
6. Does it give the owner a good interview story (situation, action, result)?

Example shapes by field (adapt them, don't copy):

| Field | Proof-of-work shape |
|---|---|
| Software / data | A small open-source tool or library with tests and a README that solves a problem the target role cares about |
| Teaching / training | A free, polished mini-course or lesson pack on a public page, with learning objectives and an assessment |
| Design / UX | A case study: problem → research → iterations → result, for an invented or public-domain product |
| Marketing / content | A teardown article of a public campaign, or a small campaign run for a non-profit, with honest results |
| Healthcare | A patient-education leaflet or evidence summary (no patient data), or a published CPD certificate |
| Finance / analysis | A public-data model or dashboard with a written memo of findings |
| HR / operations | An onboarding playbook or process template written up as an article |
| Research / academia | A preprint, poster, open dataset or explainer thread |

## 3. Add it to the profile (once it exists)

- **Projects:** name, dates (add an end date if it's finished, or it shows "– Present"), associated role (personal
  projects: none), 2–3 line description with the public link, and skills.
- **Featured:** add the link first in the list. If the preview fails, retry (see [linkedin-gotchas.md](linkedin-gotchas.md)).
- Optional: one line in About pointing to it.
- Each step goes through draft → OK → save → verify, like any other change.
